# Contributing to Komadrona Review

Komadrona Review accepts code, accessibility, research, editing, and correction contributions. Medical and examination content has a higher evidence requirement than ordinary website copy.

## Before contributing

- Do not submit actual, leaked, recalled, reconstructed, or claimed licensure-examination questions.
- Do not submit commercial reviewer scans, textbook scans, faculty test banks, patient records, or private student data.
- Do not use government or school seals, logos, or branding without documented permission.
- Do not state or imply that an agency, school, instructor, or professional endorses the project without written authorization.
- Do not publish credentials, license numbers, private contact information, or affiliations without consent.

## Content contribution requirements

A review-content proposal must include:

1. the examination domain and topic;
2. original wording;
3. the exact primary source title and issuing body;
4. the source date or version;
5. the relevant section, page, or paragraph;
6. the date the source was checked; and
7. a note identifying any uncertainty, conflict, or potentially superseded guidance.

AI-generated text is not a source. AI-assisted drafts must be checked against the cited primary materials before submission.

## Practice-question requirements

Every proposed question must include:

- an original stem and answer choices;
- one best answer;
- a concise rationale;
- a source supporting the answer;
- a difficulty label; and
- confirmation that the question was not copied or recalled from an examination or proprietary test bank.

## Review statuses

Only maintainers may assign publication status:

- Draft
- Source checked
- Clinically reviewed
- Needs re-verification
- Archived

“Clinically reviewed” requires documented review by a qualified professional. Informal feedback is not sufficient.

## Development workflow

1. Create a focused branch from the current default branch.
2. Keep one clear scope per pull request.
3. Run `npm install` and `npm run build`.
4. Describe what changed, why, and which checks were performed.
5. Do not merge failed checks or unresolved medical-content concerns.
